# The llama.cpp release built into the game (Steam and the test builds).
#
# Every game build fetches exactly this release (build.yml runs
# `fetch_engine.py --tag pinned`), so the Windows, macOS and Linux builds of one
# commit - and every re-run of it - ship the same, tested engine. The weekly
# live check (live-check.yml) plays a real game with this release *and* with
# the newest one, so it says when a newer engine is worth moving to.
#
# The lines after the tag pin each archive's SHA-256 (the format `sha256sum`
# prints): fetch_engine.py refuses a download whose bytes - or whose
# fingerprint on GitHub - differ, so a file replaced on the release after it
# was reviewed never reaches players. The in-game Clef installer
# (install_tagged_release) checks the same lines and fails closed when the pin
# has no digest for an archive it would download, or when GitHub's digest
# disagrees. That includes the CUDA 13/12 builds, their CUDA runtime zips,
# Vulkan, and CPU, for each OS this installer can select. Windows CUDA runtime
# zips omit the build tag in the filename GitHub publishes.
#
# To move: change the tag below (it must have Windows vulkan + cpu, Linux
# vulkan + cpu and macOS arm64 builds), replace the SHA-256 lines with the new
# archives' (download them from the release page and run `sha256sum` on them,
# or copy the "sha256:" digests the release page shows), let CI build it, and
# play a test build.
